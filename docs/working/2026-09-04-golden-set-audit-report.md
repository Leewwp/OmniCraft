## 2. 标题重合度审计（核心数字）

方法：对每条 semantic 查询，取期望文档标题（剥书名号/IP 前缀/括注）为「标题核心」，计算最长连续公共子串（LCS）、覆盖率、副题整段复读、英文实词连续命中。

- **semantic 48/48 = A 档（标题复读级）**；B 档（长片段）0 条；C 档（真语义）0 条。
- 副题整段复读 37/48；英文词片复制 11/48（即 11 条不自然查询）。覆盖率 ≥0.5 的 28 条；0.3–0.5 的 17 条；<0.3 的 3 条（均为副题整段复读，如 gs-c2-0084「黄风以北」4 字=副题全文）。
- 极端例子：gs-c2-0093 覆盖率 1.00（标题核心 9 字全在查询里）；gs-c2-0105「峡谷月台」覆盖率 1.00；gs-c2-0070 覆盖率 0.73 且 16 字连续原文。
- exact 对照组：64/64 查询=完整标题逐字相等。
- 结论：当前 semantic 与 exact 在「可用标题关键词命中」上无本质差别，两层合并报「RAG 检索效果」必然虚高。逐条明细重跑 `python3 scripts/corpus/golden_set_audit.py` 查看。

## 4. 修改后的分层方案（196 条，2026-09-04 用户裁决）

| 新层 | 配额 | 来源 | 判分口径 |
|------|------|------|---------|
| known_item_exact | 64 | 现 exact 全保留（48 global + 16 ip_scoped 子报），**定位为标题查找诊断集**，只验证索引/过滤/链路，不用于证明语义能力 | Recall@1/@3、MRR；ASCII 冒号子集在 #319 修复前单独标注不计分 |

| body_evidence | 24 | 新增：只给正文/摘要出题，答案仅正文可得；span 必须对齐真实 chunk | Recall@K、MRR、nDCG@K |
| hard_neighbor | 16 | 新增：同 IP 多候选；hard negative 从真实 Top-K 挖掘后人工判 expected/acceptable/forbidden | Recall@K（主目标）+ 误中 forbidden 率 |
| no_answer（域外 12 + 域内 8） | 20 | 域外=去重后 12 条（策略分档）；域内=新增 8 条真·近邻诱导题 | 拒答/诚实声明率、幻觉率；检索层与回答层分开判（见 §5） |
| visibility | 24 | 现层保留；principal_key 落库 | 四泄漏面泄漏率（结果/引用/正文/工具事件）=0 硬门，单独统计 |

**no_answer 双策略**（v2 标注规范落地）：
- `strict_not_found`：事实问题/指定作品查找。无证据必须明说找不到，禁止编造；检索层 trap_hit@10 仅作诊断，回答层引用任何库内相似文顶替算错。
- `related_recommendation_allowed`：内容发现型请求。正确行为=明确「没有完全对应内容」+ 可推荐真实存在的相似作品；把相似文标 forbidden 反而惩罚正常推荐。判错=把相似文谎称为精确对应、或编造不存在的内容。

**身份模型（可执行）**：viewer_context v2 = `{"principal_key": "anon" | "fixture:viewer-anon" | "fixture:author:aXX"}`，引用冻结的 principal registry（注入时已建 viewer-anon 用户 + 56 条 follower_edges + 作者账号）；关注关系由 fixture 数据预先建立，**不由每条 case 声明 follows[]**。相关性层（exact/semantic/body/hard/no_answer）principal=anon（或 viewer-anon，可见性等价），目标只用 public；visibility 层在 anon 与 fixture:viewer-anon 双身份下跑四面零泄漏。运行时只有 is_public 布尔——**v2 不假装执行 fans_only 语义**，语料原始 visibility 保留为元数据；authorized_private（作者 fixture）为可选扩展层待确认。

**标注三档**：`expected`（最应该返回/必须引用）、`acceptable`（返回也合理）、`forbidden`（相似但明显不满足关键约束）。hard negative 必须人工判断，不机械把同 IP 相似文全标错。

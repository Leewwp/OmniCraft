## 1. 执行摘要

**总评**：OmniCraft 的浏览面（首页/原创区/IP 库/内容详情/收藏/系列/搜索）完成度和视觉质量较高，设计系统执行良好（token 使用、卡片体系、双主题）。但**「创作—审核—反馈」的闭环链条存在系统性断裂**：判官链路（考试字段断裂、闭案不生效）、申诉链路（封禁用户死链）、举报链路（admin 处理 100% 静默失败）、PR 链路（new_text 丢弃、入口断头）、通知触达（本地无 worker 全断）五条链路各自断在「最后一公里」——后端能力大多存在，但前端入口缺失、前后端契约错位或状态不回写，用户视角表现为：**发了没人审、审了不生效、生效了不知道、失败了没出口**。此外发现两处必须优先处理的安全问题（用户 email 匿名可取、banned 内容匿名可读）与一处配置危险项（admin config 保存会静默改坏惩罚系数）。

## 3. 功能发现明细

**完整 96 条（F-001~F-096，含类别 [A/B/C]、严重度、证据 `文件:行号`、复现步骤、修复建议方向）见交接清单 `2026-09-01-design-audit-findings.md`，其证据细节与全部 curl/psql 复现记录见 5 份域笔记。** 此处按域给出结构摘要：

### A 域 · 账号/发布/审核/申诉（22 条：P0×3、P1×6、P2×9、P3×4）
核心链路断裂集中在「作者视角的可知性」：作者看不到自己非 published 内容（A-02）、被封原因零触达（A-08）、冻结/封禁信息不透明（A-09）、编辑绕审（A-05）+ 编辑无 UI 入口（A-06）并存。banned 对 AI 通道确为终态（F1 断言证实），但 auto-hide 是无守卫的 under_review 入口（A-03 补充）。

### B 域 · IP/PR/判官（20 条：P0×2、P1×10、P2×6、P3×2）
判官体系三处硬断裂：考试字段（B-01）、闭案不回写（B-02）、撤权词表（B-09）；判官看不到内容本体按编号盲投（B-04）——内容安全暴露检测的结论是**反向问题**：不是敏感内容直出，而是「无内容可看」+「媒体 URL 匿名直链」并存。PR 链路 new_text 在提交时即丢弃（B-05），DiffViewer 右栏结构性为空。

### C 域 · 社区/通知/反馈/主页（18 条：P0×1、P1×5、P2×10、P3×2）
通知触达矩阵（23 行）显示：内容状态转移、判官闭案、PR 提交、协作邀请、讨论回复、关注 IP、举报处理、rehab 完成、mention 全部无有效通知；环境层面除 admin 广播外全部通知依赖 cmd/worker，文档化本地启动方式下全断（C-02）。讨论区双路由导致审核与信誉门双绕过（C-04/C-05）。

### D 域 · 收藏/系列/搜索/Agent（16 条：P0×1、P1×4、P2×7、P3×4）
正面结论：收藏集后端语义完整（默认集自愈、409、私有 404 不泄漏、is_favorited 单一源、旧 favorites 零残留）、浏览历史与 SeriesNav 质量高、发布助手（自动填充+undo+violation 阻断）实现到位。问题集中在入口可达性（收藏页、PR 入口）与契约错配（trending、考试字段）。

### E 域 · Admin/横切（20 条：P0×1、P1×8、P2×8、P3×3）
Admin 的「处理动作」类功能大面积前后端字段断裂（reports resolve、config 保存、封禁 reason 丢弃）；「查看」类功能基本可用但筛选/分页/批量普遍缺失。错误码映射：user-facing-error.ts 仅 12 码，高频码（PUBLISH_FROZEN/APPEAL_EXISTS/ARCHIVE_* 等）裸出；SearchAgentInput 直接展示后端英文 message（Key Rule 12 违例）。zh/en 词条集合一致（1857/1857），抽查未见硬编码中文残留（通知标题硬编码中文是后端问题）。

# 决策票据：内容详情浮层路由与可访问性

**创建日期**: 2026-07-25

**预计失效日期**: 2026-09-25

**状态**: partially-resolved（交互/滚动/动效已定；仅 URL 与错误历史语义仍 open）

## Question

所有内容卡片入口打开内容详情浮层时，URL、浏览器返回、遮罩关闭、焦点恢复、Esc、移动端全屏层和直接访问链接应如何协同？

## Resolved on 2026-07-26

- 推荐流卡片与 Agent 引用卡片复用同一内容详情浮层，不创建 Agent 专属详情弹窗。
- 关闭后恢复来源页面的滚动位置和触发元素焦点；Agent 来源必须恢复原会话滚动位置并聚焦引用卡片。
- 桌面使用覆盖式详情层，移动使用全屏详情层；直接访问内容 URL 使用完整详情页。
- 显式关闭、遮罩点击、Esc 和浏览器返回均可关闭；浮层内部点击不关闭。

## Resolved on 2026-07-27/28

- 推荐、分区页、IP 详情、Agent 引用与浮层内关联内容均使用同一浮层；关联内容压入无硬上限的内部栈，完整详情页仅服务直达链接。
- 返回按钮、Esc、浏览器返回逐层弹出；右上关闭和背板点击退出整个内容栈。返回文案显示来源或上一条内容标题，不显示层数或解释文本。
- 每层记忆唯一内部内容滚动容器；背景 html/body 锁定，dialog 与外壳不滚动，顶部返回/关闭栏位于滚动主体外。
- 弹窗外壳与封面共享开合进度（300/240ms）；Agent 引用入口复用，缺缩略图或触发卡不在视口时降级居中轻缩放+淡化；reduced-motion 为 100ms 纯淡化。
- 私信聊天浮层和图片预览可继续叠加在内容详情之上；Esc/背板/移动返回只关闭最上层，关闭后恢复下层滚动与触发点焦点。
- 内容详情内标题身份栏和右侧创作者栏的资料浮层优先在头像/昵称下方居中、下方空间不足时上翻并限制在详情可视区；评论发布者资料浮层继续既有动态定位。私信聊天浮层在桌面视口居中，不继承资料浮层锚点。

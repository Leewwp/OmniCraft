## Problem Statement

用户（项目负责人）对当前 UI 有四项不满，经代码级核实全部成立：

1. **页面缺乏精致感**：同屏控件高度无档位可依——IP 详情页「进入讨论区」按钮（`px-3 py-2 text-xs`，约 33px 高，且包在无对齐类的裸 div 里）与相邻的关注按钮（h-7=28px）、内容标签（h-5=20px）、类目筛选（h-7）形成四种植被高度。根因是系统性的：`design-system.md`（唯一 token 权威）只定义了按钮变体与圆角，**不存在按钮高度/尺寸档位**；`ui-spec.md` 的 IP 详情页规格（§612）也没有 hero 区按钮规格。每个组件自行猜测高度，必然漂移。
2. **形状/动效/选中态不统一**：同一概念控件两套规范——IP 库（/ips）的分类筛选是 44px 药丸（`min-h-11 rounded-full` + aria-pressed 选中态），IP 详情的类目筛选却是 28px 圆角矩形按钮；按压动效（`active:scale-95`）各组件自由发挥，无动效 token。
3. **纯白背景单调、无辨识度**：这是现行规范的成文结果——`design-system.md` 核心原则第 3 条规定「纯白背景 #FFFFFF」，且全局样式表中页面背景、卡片、弹层全部同值 `#ffffff`，同色无层次。
4. **筛选交互不统一**：IP 库筛选是客户端 state + `router.replace`（就地刷新下方内容）；IP 详情的类目 tab 全部是链接，整页跳转到独立服务端渲染路由 `/ip/[ipId]/[category]`。同一动作两种心智模型。

另经本次核实发现一条**审计 96 条漏网的新缺陷**：IP 类目清单中 `mod` 类目的文案键误指向「其他」键，导致 IP 详情类目筛选出现两个「其他」（正确的 `home.mod` = "Mod" 文案已存在）。

## Solution

以六维设计语言裁决一次性收口上述四类问题，并按五张执行票（U-01~U-05）落地，**插队到设计审计 T 票 frontier 最前**（先换基底、功能票落在新基底上，避免同一页面被改两遍）：

| 维度 | 裁决 |
|---|---|
| 颜色 | **保持靛蓝 #4F46E5 系，不换色相**；参考图只取形态规范（其深青绿主色不采用） |
| 表面分层 | 亮色：画布 `#f5f5f5`（现成 token）+ 卡片/弹层纯白 + 1px `#e8e8e8` 描边；暗色：**卡片不动**（#0d1117），画布退深到 `#010409`（现成 `--canvas-inset` 值）。「卡片不动、画布退一档」对称策略，两侧各只改 2 个 token 值；核心原则第 3 条「纯白背景」修订为「分层画布」 |
| 形状语义 | **操作类控件**（按钮/输入框/下拉/搜索）= 8px 圆角矩形（由现 4px 提升，与卡片同档）；**筛选/类目选择控件** = 药丸（复用 IP 库形态，44px 触控高度）；**信息标签**（TagBadge/状态徽标）= 药丸保留。矩形=可操作、药丸=可选择/信息 |
| 高度体系 | 三档：紧凑 28px / 常规 36px / 表单与主 CTA 44~48px + 硬规则「**同排控件同高**」写入 design-system 组件规范；Button 组件 size 档与之对齐 |
| 选中态 | 全站筛选选中态 = **IP 库现有效果即基准**（`accent-subtle` 浅底 + `accent-emphasis` 文字 + 主色描边 + Check 图标），零新 token |
| 动效 | 全站 150ms transition（颜色/背景/边框）；`active:scale` 按压缩放仅保留主 CTA；hover 维持「加深一档」现行规则 |
| 交互模式 | 筛选一律**就地切换 + URL query 同步**（replace 不滚动），不跳页；IP 详情 `[category]` 独立路由 redirect 至 query 参数，SSR 首屏保留默认类目 |

token 换血全局只发生一次：审计 FIX-05 的 dark token 裁决（dark `--primary` → #4F46E5 系达 AA、dark `--accent-emphasis` 提亮 #818CF8、hover 对比达标）并入 U-01（定稿）/U-02（落地），T18 (#238) 收缩为 Agent 组件内代码修复并挂 `blocked_by U-02`。

## User Stories

1. 作为访客，我希望页面是浅灰画布 + 纯白卡片的分层背景，以便一眼区分内容区与页面底、页面不显得单调。
2. 作为深色模式用户，我希望画布与卡片有明暗分层（卡片浮于更深画布之上），以便深色主题下内容仍有层次。
3. 作为深色模式用户，我希望主按钮与选中态文字对比度 ≥4.5:1，以便深色下长时间浏览不累眼。
4. 作为浏览用户，我希望 IP 详情页「进入讨论区」按钮与同行/邻行的关注按钮、标签、类目筛选高度对齐，以便页面看起来精致、专业。
5. 作为浏览用户，我希望在 IP 详情页点击「图片」「文字」类目时下方内容就地刷新且 URL 同步变化，以便获得与 IP 库一致、不丢失滚动位置的筛选体验。
6. 作为浏览用户，我希望全站同类筛选控件（IP 库分类、IP 详情类目、内容类型筛选）形态、尺寸、选中态一致，以便形成操作肌肉记忆。
7. 作为移动端用户（375px），我希望筛选药丸保持可横向滚动与足够触控高度，以便小屏也能顺畅单手筛选。
8. 作为创作者，我希望发布表单里的输入框、下拉与提交按钮同排同高，以便表单整齐、填写顺手。
9. 作为 IP 创建者，我希望 IP 详情 hero 区的标签、关注、粉丝数、讨论入口排列有序（同排同高、间距成组），以便我的 IP 主页观感可信。
10. 作为内容浏览者，我希望内容详情页的类型/系列筛选就地切换，以便不离开当前阅读上下文。
11. 作为 Agent 工作台用户，我希望工作台界面在新视觉基底上渲染（气泡可读、控件高度与圆角统一），以便对话体验与前台一致。
12. 作为未来的 Agent 工作台重构执行者，我希望重构消费已定稿的统一 token（高度档/圆角/选中态/动效），以便重构不再产生新的不一致。
13. 作为管理员，我希望 admin 后台与 studio 管理页在第二批 sweep 后与前台形态统一，以便后台操作也有一致体验。
14. 作为面试演示的观看者，我希望全站视觉一致、无对齐瑕疵、亮暗两套主题都经得起细看，以便演示观感专业。
15. 作为项目负责人（简历撰写者），我希望「全部页面改动落地」作为启动投递的明确门槛被票务系统跟踪，以便投递时点有客观依据。
16. 作为开发 Agent，我希望 design-system.md 提供按钮高度三档、形状语义、选中态与动效规范，以便实现任何页面时不再自行猜测高度与状态样式。
17. 作为开发 Agent，我希望筛选控件有共享组件（含 aria-pressed、横向滚动、选中态）可复用，以便新页面接入筛选不再复制粘贴。
18. 作为设计维护者，我希望「矩形=可操作、药丸=可选择/信息」的形状语义成文，以便后续页面扩展不破坏统一语言。
19. 作为开发 Agent，我希望全局 token 只换血一次且留有对比度复算记录，以便后续所有改动基于稳定基底。
20. 作为测试执行者，我希望每张 U 票都有亮暗双主题 × 桌面/移动截图的验收标准，以便视觉回归可复查。
21. 作为浏览用户，我希望 IP 详情类目筛选不再出现两个「其他」，以便类目语义准确（mod 类目正确显示为 "Mod"）。

## Implementation Decisions

1. **颜色不换**：保持靛蓝 #4F46E5 系主色；参考图（深青绿 #2E5457 主色）仅取形态规范——8px 圆角、1px 描边分层、极轻阴影、表单控件等高。
2. **表面分层值**：亮色画布 `#f5f5f5`（复用现成 `--canvas-subtle` 值，不新增 token）、卡片与弹层保持纯白、1px `#e8e8e8` 描边；暗色卡片族全部不动（#0d1117），画布（background/canvas-default）退深至 `#010409`（复用现成暗色 `--canvas-inset` 值）。两侧各只改 2 个 token 值，规避「卡片提亮」备选方案的四 token 回归面。
3. **design-system.md 修订内容**（U-01）：核心原则第 3 条「纯白背景」→「分层画布」；设计令牌节补按钮高度三档（28/36/44-48）与「同排同高」规则；组件规范补形状语义（矩形=操作、药丸=选择/标签）、筛选选中态基准（accent-subtle 底 + accent-emphasis 字 + 描边 + Check）、动效规范（150ms transition、active:scale 仅主 CTA、hover 加深一档）；圆角档位将按钮/输入框自 4px 提升至 8px（与卡片同档）。
4. **token 换血范围**（U-02）：全局样式表表面分层两对值 + 审计 FIX-05 裁决的暗色 token（`--primary` → #4F46E5 系、`--accent-emphasis` → #818CF8、hover 对比 ≥4.5:1）+ Button 组件 size 档对齐三档高度体系。全站只此一次 token 换血。
5. **ui-spec.md 同步**（U-01）：IP 详情页规格补 hero 区按钮规格（同排同高）；IP 类目内容列表独立规格（§662）并入 IP 详情页规格（就地切换后不再是独立页面）；新增统一筛选控件（FilterPills）组件规格；`/ips` 页规格维持现状（已是基准实现）。
6. **FilterPills 共享组件**（U-03）：从 IP 库现有实现提炼——药丸、`min-h-11` 触控高度、横向滚动、`aria-pressed`、选中态（accent-subtle 底 + accent-emphasis 字 + 描边 + Check 图标）；IP 详情类目与其他筛选接入。
7. **IP 详情类目就地化**（U-03）：类目 tab 改为客户端状态切换 + URL query 同步（`router.replace` 不滚动），下方内容客户端拉取既有内容列表 API（带类型参数）；`/ip/[ipId]/[category]` 独立路由 redirect 至 query 参数形式；SSR 首屏保留默认类目；i18n 复用既有类目键。
8. **顺手收编的缺陷**（U-04）：mod 类目文案键误指「其他」键（改指 `home.mod`）；「进入讨论区」按钮裸 div 补对齐/同高处理。
9. **sweep 分两批**（U-04/U-05）：第一批 = 公开页 + 用户侧（studio 除外）+ Agent 工作台；第二批 = admin 后台 + studio 管理页。两批均以「同排同高、形状语义、选中态、动效」四规则逐页检查落地。
10. **批次与依赖**：U-01 → U-02 → {U-03, U-04, U-05 并行}。U 批次整体插队到审计 T 票 frontier 最前。
11. **T18 (#238) 改造**：token 裁决部分移入 U-01/U-02；该票收缩为「Agent 气泡/引用卡对比度代码修复」，挂 `blocked_by U-02`（在新 token 上修）。
12. **重构接口预留**（不在本 spec 立项）：Agent 工作台重构排在 T18/T19/T20 之后；IP 详情重构排在 T17/T24 之后；两者由用户在独立会话出方案后另立票，前端为主、允许少量后端改动。
13. **车道**：U-01~U-05 全部 light（无安全/迁移/auth 面）；U-02 必须附亮暗双主题全站目检清单与对比度复算记录。
14. **零后端改动**：U 票全部为前端 + 文档改动；就地切换消费既有 API。
15. **执行状态**：2026-09-02 用户整合裁决已解除冻结；U-01→U-02→{U-03,U-04,U-05} 的跨批次总序以 `docs/working/2026-09-02-integrated-execution-order.md` 为准。

## Testing Decisions

- **最高缝 = 渲染后的页面本身**：沿用项目既有 UI 验证门（AGENTS.md Step 4），浏览器（Playwright MCP）亮暗双主题 × 1440/375 截图存 `screenshots/`；不新建测试基建。
- **U-02（token 换血）**：`npm run build` / `npm run lint`（类名与 i18n parity）+ `verify-project.sh --full`（mocked e2e 契约，确认全局类改动不破坏契约测试）+ 对比度复算（沿用审计的 WCAG 计算方法，所有涉及色对 ≥4.5:1，结果写入 PR 描述）+ 全站双主题目检清单。
- **U-03（就地化）**：路由 redirect 断言（沿用既有 e2e mock 路由表模式）+ 浏览器交互验证（切换不跳页、URL 同步、刷新后状态保持、旧链接 redirect 正确）。
- **U-04/U-05（sweep）**：逐页截图对比（改造前后、亮暗、双断点）；对齐类修复以「同排控件渲染高度一致」为目检判据。
- **文档票（U-01）**：design-system.md 与全局样式表现值差异逐条清单化（供 U-02 消费），无代码可测。

## Out of Scope

- **主色/色相更换**：参考图深青绿不采用（可留作未来主题选项）。
- **两个重构本体**（Agent 工作台、IP 详情）：由用户在独立会话出方案另立票；本 spec 只预留依赖边与规范输入。
- **任何后端 API/Schema/迁移变更**：U 票零后端。
- **字阶变更**：现有五档（12/14/16/20/24）与参考图量化结果兼容，不动。
- **暗色「卡片提亮」备选方案**（画布不动、卡片改 #161b22）：已裁决弃用（四 token 回归面翻倍）。
- **admin/studio 的功能修复**：属审计 T 票范围，U-05 只做视觉统一。
